  "schemaVersion": 1,
  "model": "serializable",
  "initial": {"x": "x0", "y": "y0"},
  "transactions": [
    {"id": "A", "status": "committed", "ops": [
      {"type": "read", "key": "x", "version": "x0"},
      {"type": "write", "key": "y", "version": "y1"}
    ]},
    {"id": "B", "status": "committed", "ops": [
      {"type": "read", "key": "y", "version": "y0"},
      {"type": "write", "key": "x", "version": "x1"}
    ]}
  ]
} 这份日志要求 A 在 B 前、B 又在 A 前，形成两事务环。报告保留依赖的键、操作下标、版本和来源，并寻找图中全局最短的有向环。 serializable  检查整个事务的串行执行； strict-serializable  再尊重共同单调观察时钟中明确先完成、后开始的约束。 事务状态为 committed/aborted/unknown；缺少结果、来源或共同时间时明确指出。 versionOrders  是可选的采集事实。缺少多写者顺序时，只在其余观察充分且规模允许时搜索补全。 searched  只证明某个可能执行成立，不能变成已观察到的数据库顺序。缩减只裁剪原始声明。 详见  输入格式 、 JSON Schema 、 算法设计  和  独特性范围 。范围/谓词查询、自动 SQL 插桩、append/list 模型及完整隔离级别分类尚未实现。 # API 与预算约定 保留  analyze 、 reduce_history 、JS  analyze / shrink  和 CLI 默认行为。推荐显式使用高级入口： import {analyzeWithOptions, shrinkWithOptions, replayReport} from './dist/sdk.mjs';
