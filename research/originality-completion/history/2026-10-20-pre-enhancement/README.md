## 实际新增的检查

`scripts/verify_source_originality.py` 只读打开已有 56 个发布 ZIP，先验证每个 ZIP 与上一轮清单的 SHA-256 一致，再把本项目生产 MoonBit 源码与其中的生产 MoonBit 源码比较。第三方源码不解压落地、不导入、不编译、不执行。

- 本项目 15 个生产 `.mbt` 文件，22,458 个词法 token。
- 第三方 56 个固定版本 ZIP，2,056 个生产 `.mbt` 文件，2,677,327 个 token。
- 排除 1,430 个测试文件和 17 个带明确自动生成声明的文件；具体排除项逐一保存在结果中。
- 对保留所有标识符、字面量和运算符的 token 序列，去掉空白与注释，逐个比较所有 32-token 种子，延长到最大相同片段，并验证实际 token 相等，避免哈希碰撞误判。
- 同时比较完整 `///|` 块的一致标识符替换版本，保留关键字、类型名和字面量，能够发现整块只改变量名的候选。
- 修正前主筛查门槛为 80 token、8 行，候选为 0。更敏感的 40 token、5 行筛查得到 2 个候选，已逐个人工核对；原始结果固定保存在 `before-remediation-source-clone-screen.json` 和 `before-remediation-source-clone-sensitive-screen.json`。
- 检测器自测包括真正端到端的受控相同代码、改名代码和不相关代码三类；自测没有运行这些受控代码，只对文本执行检测。

检查结果绑定 `local_sources` 中每个源文件的 SHA-256。代码更改后必须重跑，不能把历史的 0 候选当作新版本结论。

## 两个具体文本交集

敏感筛查查明了本项目 `wire/wire.mbt:165–167` 的 `"0", "1", …, "f"` 十六进制字母表，与下面两个文件存在一个 44-token 相同片段：

1. `Magic486/moonnetlink@0.2.0` 的 `journal/hex.mbt:4–6`。
2. `DDD12345-D/moon-snmp@0.3.0` 的 `e2e/v3query/main.mbt:562–564`。

匹配片段含标准 16 个十六进制字符、逗号及周围通用语法。三个函数的名称、变量和输出累积方法不同。人工结论是通用编码字母表交集，不是 PTP 关联、correction 精确计算或 BMCA 算法复制。记录没有把这一具体交集隐藏在阈值以下。

可执行处置是复用经过核实的标准库十六进制编码，或在没有适用标准 API 时用 nibble 数值构造字符，保留相同输入输出与往返检查。`moonbitlang/core@0.1.20261019+b1a0e846e` 的发布 ZIP 已核实包含 `encoding/hex/pkg.generated.mbti`，其中正式接口是 `pub fn encode(BytesView) -> String`，因此优先复用此接口。重命名变量不能作为解决方法。后续如完成处置，应另存处置后的筛查，不覆盖本次原始发现。

实际处置已落实：`wire.to_hex` 改为调用 `@hex.encode(b[:])`。修正后对同一 56 包再次执行更敏感的 40-token/5 行检测，并且额外纳入所有生成文件和第三方测试文件：3,503 个 MoonBit 文件、4,841,530 tokens，候选为 0，生成文件排除数为 0、测试文件排除数为 0。当前结果绑定修正后各生产文件哈希，见 [after-hex-reuse-56-inclusive.json](after-hex-reuse-56-inclusive.json)。这解决了已发现的字母表重复实现，不消除各产品原有的功能交集。

检测器同时加强了排除规则：仅文件最前方真实注释区的明确 `Generated by/from`、`automatically generated` 或 `@generated` 声明才能标记生成；字符串中的文字、函数内部示例以及单独的 `do not edit` 不会误排。`--include-generated --include-tests` 可执行不排除这两类文件的额外检查。源文件上限提高为明确的 32 MiB，可通过 `--max-source-bytes` 调整；超限、非 UTF-8 等情况逐文件列出，不计成已扫。

## 全生态源码检查的可行性与范围

56 个缓存 ZIP 共 16,390,625 字节，均值约 293 KB、中位数约 105 KB、最大约 2.90 MB。用该非随机样本线性外推 3,117 个最新版本约 0.91 GB；这不是统计可靠上界，但说明不能仅以数量多为由拒绝执行一次最新发布版本源码采集。

实际全量应绑定最新完整索引，逐包保留版本、URL、ZIP SHA-256、限流重试、下载/解码状态、显式大小上限和排除项。4 个并发、有限重试、按官方 `download.mooncakes.io` 发布 URL 只读采集是合适的起点。未取得、损坏或被上限跳过的包必须单列，不能计为已完整源码核查。

本目录目前这份检测清单的直接覆盖仍为 56 个固定源码包。检测脚本可通过 `--audit` 指定扩展后的同结构清单复用。全量索引、全量发布源码采集、源级 token 检测与语义人工复核是四个不同层次，不能把完成其中一层写成全部层次完成。

## 全量源码增量语义审查

全量采集过程中，`manual-semantic-dispositions.json` 为人工实际复核过的每个强命中保存包名、版本、ZIP SHA-256、源码路径、行号以及上下文判断。`scripts/review_source_semantic_hits.py` 只把这些记录与当前结果连接，不能自动生成“人工已审”结论；新的未审强命中会保留在 `full-source-semantic-review.json` 的 `pending` 中。普通 `follow-up` 词语另列，不把一般后续工作文字冒充 PTP Follow_Up 实现，也不冒充全部词语都经过人工源码上下文审查。

已确认必须保留的一项新具体交集是 `hevienz/moonbit_libbpf@0.10.0` 的 `vmlinux.h:118785–118807`：其随包发布的 Linux 内核类型声明包含 `clock_identity`、`port_identity` 和完整 `ptp_header` 标准公共头，实际列出 message_length、domain_number、flag_field、correction、source_port_identity、sequence_id、control 与 log_message_interval。全包查找这三个类型名只定位到声明本身，未见本包使用处。**这是真实的 PTP 标准头结构交集**，不能笼统说生态不存在任何 PTP 字段或布局；同时它也不是一个 MoonBit PTP 报文解码、two-step/E2E 关联或 BMCA 引擎。继续支持标准 wire 布局是互操作要求，改掉标准字段来追求文字不相同会破坏协议正确性。

## 复现

```sh
python3 scripts/verify_source_originality.py --self-test
python3 scripts/verify_source_originality.py
python3 scripts/verify_source_originality.py \
  --minimum-tokens 40 --minimum-lines 5 \
  --output research/originality-completion/source-clone-sensitive-screen.json
# 全量发布源码采集完成后，使用其固定索引和逐包结果：
python3 scripts/verify_source_originality.py \
  --audit research/full-source-audit/manifest.json \
  --minimum-tokens 40 --minimum-lines 5 \
  --include-generated --include-tests \
  --output research/originality-completion/full-source-clone-screen.json
python3 scripts/review_source_semantic_hits.py
```

输入是已经下载且按哈希登记的 ZIP 缓存。换机器时须按原 source-audit 清单重新取得缓存。常规产品运行和测试不依赖这些第三方源码。

本检测不能证明语义等价不存在，不能覆盖重排/大改代码、门槛以下片段、其他语言、测试、明确生成的文件、全部历史版本或未发布实现，也不能给出“永远绝对零类似”保证。
